# BUILD-ALL-05A — PASS (scoped)

## Implementation and boundaries

- The existing candidate installer exposes `--mode prepare-upgrade` and requires a root-only JSON health credential file. Only the exact pinned BUILD-ALL-04 tuple, exact known unit files without drop-ins and initially active services are accepted; ambiguous or inactive states are refused before service changes.
- The coordinator uses an exclusive nonblocking `flock`, records durable phase and process identities, checks the known unit paths, PID/start time and executable, stops the panel first and the independent AWG service second, confirms both inactive, then restarts AWG and the panel in reverse order and performs authenticated panel API and AWG public-identity health checks. Xray remains a child of the panel, not a separately managed systemd unit.
- The existing backup helper performs SQLite Online Backup under a `BEGIN IMMEDIATE` writer lock, copies private AWG configuration and keys, other panel data, the complete managed component tree including Xray's generated configuration when present, systemd units and version hashes. A private manifest records original UID/GID/mode; backup files remain private. Inventory, hashes and SQLite integrity are checked. Open writable descriptors are checked before and after, and source configuration/tree fingerprints are compared around the snapshot.
- Ordinary preparation failures attempt to restore the initially active services. A failure to restore or to durably record recovery returns `SERVICE_RECOVERY_FAILED`; incomplete snapshots are retained privately. Nonterminal durable state causes future preparation to refuse with `RECOVERY_REQUIRED`.
- This is a cooperative lock and observable-writer check, not a global filesystem freeze or durable proof against a concurrent privileged actor. PID/unit/file identity rechecks leave a residual check-to-use race. Only the known loopback HTTP panel health configuration is supported. After services restart the snapshot can immediately become stale; the result explicitly says `reuse_for_upgrade: false`. A future updater must re-establish a coordinated cut. No binary update or rollback is implemented.
